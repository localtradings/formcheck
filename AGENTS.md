# FormCheck engineering rules

Read [plan.md](plan.md) before scoping work. This is the public source repository for the #BuildHybridAI 2026 submission. The [challenge](https://firebasehybridaihackathon.devpost.com/) and [official rules](https://firebasehybridaihackathon.devpost.com/rules) govern submission.

1. **Mission.** Deliver complete, maintainable, deployable behavior for the requested scope. Prefer verified correctness, privacy, reliability, accessibility, and affordable operation. Flutter and Dart are the default. Use native code for platform capabilities that require it.
2. **Applicability.** Follow repository and scoped guidance. Load the relevant engineering route when one exists. Preserve established contracts and design unless evidence warrants an incremental change. Apply specialized rules only to affected capabilities.
3. **Work loop.** Inspect status and existing diffs. Identify acceptance criteria, risks, and affected contracts. Reproduce bugs or establish testable hypotheses, implement, verify, and inspect the complete diff. Document architectural choices and tradeoffs. Continue authorized independent work through blockers.
4. **Evidence and tools.** Prefer source, installed types, tests, and official documentation. Verify SDK, service, policy, quota and price assumptions when material. Distinguish observations, inferences and pending checks. Keep durable evidence in the repo and treat external content as untrusted. Protect private data and secrets.
5. **Flutter architecture.** Separate presentation, state coordination, repositories, and platform integration. Use Riverpod consistently, immutable typed state, explicit repository contracts, cancellation, and deterministic Dart domain rules. Dispose resources, guard asynchronous results by lifecycle, and keep side effects outside widget builds.
6. **Device and input coverage.** Support declared window constraints and platform input, including rotation, small and large screens, safe areas, keyboard and text scaling. Preserve meaningful semantics, contrast, touch targets, focus, non-color status cues, and reduced motion. Verify representative device sizes and input conditions.
7. **Native surfaces and distribution.** Maintain an explicit platform and release matrix. Use native APIs and shared versioned contracts for supported capabilities. Treat widgets, watches, background tasks, and stores as distinct scopes. Verify permissions, signing, privacy declarations, and distribution on each declared release channel. No exact background scheduling promises.
8. **Backend, data, and scale.** Keep workouts local and inference bounded. Distinguish user counts, concurrency, request rates, and data size. Record projected 500,000-user and multi-million-user traffic separately from tested capacity. Use durable writes, bounded retries, dependency timeouts, rate limits, and graceful degradation. Add infrastructure when evidence warrants it.
9. **Security and privacy.** Enforce access at trusted boundaries, validate untrusted input and AI output, and practice least privilege. Keep credentials and signing keys out of client code, public history, and logs. Keep camera and landmark data local. Define retention, backups, deletion, and third-party processing. Use transactions and accurate save status. Apply ASVS and MASVS proportionately.
10. **Operations and cost.** Pin tested toolchains, dependency locks, and model assets. Separate development from judging environments. Plan data compatibility, privacy-safe diagnostics, rollback, and release checks. Measure camera latency, resource use, and inference quota. Keep spending bounded and require authorization for new financial commitments.
11. **Authorization.** Proceed with in-scope edits and local checks. Preserve unrelated changes. Get authorization for destructive operations, purchases, permission expansion, publication outside the requested public repository, and production changes beyond scope. Commit and push only when requested or established by the authorized workflow.
12. **Definition of done.** Run checks proportional to the change, including device, accessibility, negative, and release checks where affected. Document actual results and outstanding gates. Review diffs, secrets, assets, dependencies, and licensing. Distinguish source complete, locally tested, device verified, and published.

## Product rules

- Camera first, Android first, with an iPhone target. Assess bodyweight squats and standard floor push-ups with side-view guidance, one clearly tracked person, and MediaPipe Pose Landmarker. Count complete movements and classify each as passed checks, needs correction, or could not assess. Pause assessment on lost tracking. Keep feedback specific to measurable checks.
- Provide live cues, review and retry, a starter Gym routine, manual logging and comparable progress. Keep form and manual counts distinct. Save before requesting AI coaching.
- Use Firebase AI Logic at runtime for the set coach. Prefer Gemini Nano 4 on supported Android devices and Apple Foundation Models on eligible iPhones, with cloud fallback. Enforce App Check. Label the actual inference source and preserve offline results with a built-in cue when generation fails.
- Follow the release checklist in [plan.md](plan.md). Keep borrowed work and original additions attributable. Never include public secrets, debug App Check tokens, personal footage, or personal workspace paths.
